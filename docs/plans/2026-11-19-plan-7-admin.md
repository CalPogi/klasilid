# Plan 7: Admin section for the owner — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An owner-only admin section in the Klasilid web app (Schools, Teachers, Readers) behind password plus two-step sign-in, so the owner never needs the SQL editor for setup again.

**Architecture:** One new Edge Function `admin` (JWT-verified; checks `aal2` and `role = 'owner'`, then uses the service role) backed by three `security definer` SQL functions for overview, retiring and deleting. The web app recognises an owner at sign-in, keeps the owner's session in memory only (never in the device's saved login or offline database), runs Supabase TOTP two-step, and shows the admin screens built from the approved boards.

**Tech Stack:** Svelte 5 runes, supabase-js 2 (auth MFA TOTP), Supabase Edge Functions (Deno), Postgres migrations tested in PGlite, vitest + @testing-library/svelte.

**Spec:** `docs/2026-11-19-admin-design.md` (approved 2026-11-19). Approved screens: `docs/mockup/admin/Admin.dc.html`, `AdminPhone.dc.html`, `TwoStep.dc.html` (laptop and phone via container query). Main design: `docs/2026-11-15-klasilid-design.md`.

## Global Constraints

- The owner reads no learner data: no names, attendance, cards or corrections reach the admin section; no RLS policy is added for the owner.
- Every admin request is refused (403) unless the token is `aal2` and the caller's `profiles.role` is `'owner'`.
- Codes, keys and pairing codes are shown once and stored only as sha256 hex, in the scripts' exact formats: school code `XXXX-XXXX` from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, hash = sha256 of the 8 characters without the dash, upper case; reader id `KD-NNNN`; reader key = 32 random bytes base64url; pairing code = 8 digits; each hashed as sha256 of the plain value.
- Retired readers keep their taps; deleting a teacher is a full delete in one transaction, then the excuse-letter photos.
- Delete and retire need the typed username / reader id; the function compares exactly.
- The owner path never opens, clears, reads or writes the device's offline database (`db.meta`, `db.outbox`, any table).
- UI markup, classes and copy come from the approved boards exactly; the laptop uses the mockup shell (`.app.full`, `.side`, `.cls-head`, `.panel`, `.tbl`, `.modal .box`), the phone uses the phone frame classes (`.scr`, `.rows`, `.rowi`, `.fnav`, `.sheet`). Laptop/phone switch with the existing `phone` store (`apps/web/src/lib/layout.ts`).
- No real learner data, school codes, keys or passwords in code, tests or screenshots. No secrets in the repo.
- Deploying (migration push, function deploy) is the owner's step, done only with his OK.

## Review Focus

1. **Owner leaves without signing out on a teacher's device** (closes the tab on his mother's laptop): her next sync must still run as her, and the owner's session must be gone. Pinned in Task 5 (`owner sign-in leaves the saved login untouched`).
2. **Two-step setup abandoned halfway** (closed at the QR step): the next sign-in must offer setup again instead of failing on a leftover unverified factor. Pinned in Task 6 (`removes an unverified factor before enrolling again`).
3. **A retired reader keeps uploading queued taps**: each call gets 401 at once and no tap row is added; the class's old taps stay. Pinned in Task 1 (`retire replaces both hashes and keeps taps`) and Task 4 (`a retired reader is refused and not marked seen`).
4. **Double click on "Add reader" / "New code"**: exactly one reader or code is made and the shown-once screen shows that one. Pinned in Task 7 (`the add button is disabled while the request runs`).
5. **The owner's token expires or drops to aal1 mid-session**: the admin section returns to the code screen or sign-in with a message, never a blank or half-filled list. Pinned in Task 7 (`a 403 sends the owner back to two-step`).

### Task 3: The `admin` Edge Function

**Files:**
- Create: `supabase/functions/admin/handler.ts`, `supabase/functions/admin/index.ts`
- Test: `supabase/tests/admin-handler.test.ts`

**Interfaces:**
- Consumes: Task 1's three SQL functions (through deps), Task 2's secrets.
- Produces:
  - `type Caller = { userId: string; aal: string }`
  - `interface AdminDeps { roleOf(userId): Promise<string | null>; overview(): Promise<Overview>; addSchool(name): Promise<string>; schoolExists(id): Promise<boolean>; setSchoolCode(schoolId, hash): Promise<void>; classExists(id): Promise<boolean>; readerExists(id): Promise<boolean>; insertReader(r: { id; classId; keyHash; tokenHash }): Promise<void>; setReaderSecrets(id, keyHash, tokenHash): Promise<boolean /* false if missing or retired */>; retireReader(id, actor): Promise<boolean>; usernameOf(teacherId): Promise<string | null>; deleteTeacher(teacherId, actor): Promise<{ classIds: string[] }>; removeClassPhotos(classIds): Promise<string[] /* class ids whose photos failed */>; audit(action, rowId, actor): Promise<void> }`
  - `handleAdmin(caller: Caller | null, body: unknown, deps: AdminDeps): Promise<{ status: number; body: unknown }>`
  - Request `{ action, ... }`; responses: `overview` → Overview; `addSchool {name}` → `{ schoolId, code }`; `newSchoolCode {schoolId}` → `{ code }`; `addReader {classId}` → `{ id, key, pairingCode }`; `newReaderKey {readerId}` → `{ key, pairingCode }`; `retireReader {readerId, confirm}` → `{ ok: true }`; `deleteTeacher {teacherId, confirm}` → `{ ok: true, photosLeft: string[] }`; `removeClassPhotos {classIds}` → `{ photosLeft: string[] }`. Errors: `{ message }` with 400 (bad input, confirm mismatch: `'Type <x> exactly to confirm'`), 403 (`'Two-step sign-in needed'` for aal1, `'Owner only'` for non-owner), 404 (`'Not found'`).
  - `index.ts`: deployed **with** JWT verification; reads `sub` and `aal` from the already-verified bearer token's payload; CORS like `signup`; implements deps with the service-role client (`rpc('admin_overview')`, `rpc('admin_retire_reader')`, `rpc('admin_delete_teacher')`, `storage.from('excuse-letters').list(classId)` + `remove`).
